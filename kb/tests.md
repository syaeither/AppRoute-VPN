# Проверки

## Автоматические тесты

```bash
python3 -m unittest discover -s tests -v
python3 -m approute --help
```

Набор из пяти тестов проверяет извлечение адресов/DNS/MTU, отказ от hooks, обязательность DNS, некорректный адрес и откат ресурсов при ошибке `wg setconf` до переноса интерфейса. Системные команды в тесте отката подменены; сеть и реальные ключи не используются.

Последний подтверждённый запуск при реализации MVP: 5/5 успешно. Модульные тесты не подтверждают реальное подключение, DNS, IPv6 или поведение GUI.

## Ручной интеграционный сценарий — пока не выполнен

Нужны Linux с WireGuard, системные зависимости, права root и действительный конфиг сервера.

1. До подключения выполнить `curl https://api.ipify.org` в обычной сети и записать IP хоста.
2. Выполнить `sudo python3 -m approute up /absolute/path/provider.conf`.
3. Выполнить `sudo python3 -m approute run -- curl --max-time 20 https://api.ipify.org`; сверить IP с ожидаемым выходом VPN. Совпадение IP само по себе не доказывает ошибку, если выходы совпадают по устройству сети.
4. Через `status` проверить handshake и рост счётчиков. Повторить обычный curl хоста и убедиться, что его маршрут сохранился.
5. Проверить доменное имя и доступ по IP внутри namespace; при наличии IPv6-конфига отдельно проверить IPv6.
6. Отключить тестовый сервер и создать новое соединение внутри namespace с тайм-аутом: оно должно перестать проходить. Обычная сеть хоста должна работать. Вернуть сервер.
7. Запустить долгоживущее приложение через `run`, убедиться, что `down` отказывается отключаться и показывает PID. Закрыть приложение и повторить `down`.
8. Проверить отсутствие namespace и DNS-файла после отключения; повторить цикл подключения.

Не публиковать ключи и конфиг в результатах. Фиксировать дату, ОС/ядро, версии Python/ip/wg, сценарий, результат и очищенные от секретов ошибки в `progress.md`.
