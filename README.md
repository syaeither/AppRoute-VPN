# AppRoute VPN

**AppRoute VPN — утилита для Linux, которая запускает выбранные приложения через WireGuard VPN, сохраняя обычную сеть для остальных программ.** Проект находится на стадии минимальной рабочей версии (MVP): доступен командный интерфейс, а реальное подключение к VPN ещё требует интеграционной проверки.

## Для чего нужен проект

При системном подключении VPN через него нередко начинает идти трафик всех приложений. AppRoute позволяет выбирать программы при запуске: например, открыть отдельный браузер через VPN, а мессенджер, игры и другие приложения оставить в обычной сети. Это удобно, когда специальный маршрут нужен только одному инструменту или конкретной рабочей задаче.

Возможные сценарии:

- Запустить браузер через VPN-сервер, сохранив обычное подключение для остальных приложений.
- Выполнить curl, загрузчик или другой консольный инструмент с выходом через VPN.
- Проверить доступность своего сервиса из сети VPN-сервера.
- Изучить на небольшом проекте сетевые пространства Linux, WireGuard, маршрутизацию, DNS и запуск процессов с разными правами.

AppRoute не предоставляет VPN-сервер и учётную запись: нужен собственный сервер или провайдер, выдающий совместимую конфигурацию WireGuard. Скорость и доступность зависят также от сервера и его маршрутизации.

## Как это работает

Программа создаёт отдельное сетевое пространство Linux — namespace `approute-vpn`. У запущенного внутри приложения собственный набор интерфейсов и маршрутов: loopback и WireGuard `arwg0`. Прямой маршрут через физический интерфейс хоста туда не добавляется.

WireGuard-интерфейс сначала создаётся и настраивается в сети хоста, затем переносится в namespace. Зашифрованные UDP-пакеты по-прежнему отправляются через сеть хоста к VPN-серверу. Внутри namespace трафик приложения направляется через WireGuard; обычные приложения хоста продолжают пользоваться своей сетью. Этот механизм описан в [официальной документации WireGuard](https://www.wireguard.com/netns/).

Выбор приложения происходит командой `run`. Его дочерние процессы наследуют сетевое пространство. Уже работающие программы автоматически не переводятся в VPN. Отдельный DNS-файл применяется при запуске через `ip netns exec`.

## Что уже реализовано

- `up CONFIG` — создание сети и настройка WireGuard по конфигурации.
- `run [--user USER] -- COMMAND` — запуск программы через подготовленный VPN namespace от обычного пользователя.
- `status` — вывод состояния интерфейса WireGuard, handshake и счётчиков.
- `down` — отключение после закрытия работающих в namespace процессов.
- Извлечение Address, DNS и MTU, проверка адресов, отказ от конфигурационных hooks.
- Попытка отката созданных ресурсов при ошибке настройки.
- Пять модульных тестов без настоящих сетевых изменений.

## Требования

Linux с поддержкой WireGuard и network namespaces, Python 3.10+, команды `ip`, `wg`, `runuser`, права sudo/root для управления сетью и действительный WireGuard-конфиг. Сторонних Python-зависимостей у CLI нет.

Для Debian/Ubuntu:

```bash
sudo apt install iproute2 wireguard-tools util-linux
```

Все команды ниже выполнять из корня проекта. Установка Python-пакета для этого не обязательна.

## Быстрый запуск

```bash
python3 -m approute --help
sudo python3 -m approute up /absolute/path/provider.conf
sudo python3 -m approute status
sudo python3 -m approute run -- curl https://api.ipify.org
sudo python3 -m approute run -- firefox --no-remote
```

Путь заменить путём к своему конфигу. Для примеров curl и Firefox должны быть установлены отдельно. Сообщение об успешном `up` означает завершение настройки интерфейса, а не проверку связи с сервером. После создания трафика проверьте handshake командой `status`.

Закройте запущенные через VPN приложения, затем выполните:

```bash
sudo python3 -m approute down
```

При активных процессах `down` откажется отключаться и выведет их PID. Команда `run` получает пользователя из SUDO_USER. При запуске из root-сессии нужно указать обычного пользователя явно:

```bash
python3 -m approute run --user alice -- curl https://api.ipify.org
```

Замените alice своим именем пользователя. UID 0 для запуска приложений запрещён. Графическим программам дополнительно нужен доступ к пользовательской Wayland/X11-сессии.

## Конфигурация VPN

Используйте конфигурацию своего WireGuard-сервера. В `[Interface]` нужны Address и DNS, а для действительного подключения — приватный ключ и корректные настройки `[Peer]`.

Поддерживаются:

- Interface: PrivateKey, ListenPort, Address, DNS, MTU.
- Peer: PublicKey, PresharedKey, AllowedIPs, Endpoint, PersistentKeepalive.

Address может содержать IPv4 и IPv6 с префиксом. DNS задаётся IP-адресами через запятую, без search domains. MTU по умолчанию 1420, допустимы значения 1280–9000.

Маршрут по умолчанию создаётся для каждого семейства адресов из Address. Для полного IPv4-туннеля у peer нужен `AllowedIPs = 0.0.0.0/0`; для IPv6 также нужны `::/0`, IPv6 Address и поддержка на сервере. При узких AllowedIPs остальные назначения не получают прямой выход через хост: передача через peer для них не разрешена.

Параметры wg-quick PreUp/PostUp/PreDown/PostDown, Table и SaveConfig не поддерживаются. Неизвестные параметры отклоняются; shell-команды из конфига не выполняются. Секретные конфиги храните вне проекта с правами 600, не добавляйте ключи в документацию или Git.

## Ограничения текущей версии

Поддерживается одна VPN-сессия. Нет GUI, SOCKS-backend, собственного TUN-перехватчика, автоматических правил по PID, переноса работающих процессов или Windows WFP-драйвера. Это первый этап идеи выборочного VPN, а не полная замена NekoBox.

Программа с единственным экземпляром может передать запрос уже работающему процессу вне VPN. Для браузера используйте отдельный экземпляр и при необходимости отдельный профиль. Наследование сети относится к процессам, действительно созданным внутри namespace.

Namespace изолирует обычные сетевые соединения, но не является полной песочницей: Unix-сокеты и службы хоста остаются отдельным способом взаимодействия. Приложения с собственным DNS/DoH сохраняют свои настройки; их собственный IP-трафик внутри namespace следует его маршрутам. Полная гарантия отсутствия утечек без интеграционной проверки не заявляется.

Не запускайте несколько операций управления одновременно и не изменяйте ресурсы AppRoute внешними командами во время его работы. При аварийном завершении или сбое очистки может понадобиться диагностика оставшихся ресурсов.

## Проверка

```bash
python3 -m unittest discover -s tests -v
python3 -m approute --help
```

При первоначальной реализации все пять тестов прошли. Они проверяют парсер и один путь отката с подменой системных команд. Настоящее VPN-соединение пока не проверено: требуется wg и действительный конфиг.

Для ручной проверки сравните внешний IP обычного curl и curl через `run`, проверьте handshake и поведение при недоступном сервере. Полный сценарий и границы покрытия: [kb/tests.md](kb/tests.md). Инструкции эксплуатации и диагностики: [kb/runbooks.md](kb/runbooks.md).
